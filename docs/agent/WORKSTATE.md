## condition-variable-lost-wakeup-audit — VERIFIED 2026-09-13 (reliability slice, found by an intermittent test hang)

- Symptom: `ffengine_volume_session_manager_tests` intermittently exceeded its 120 s CTest timeout with no output (once in a release-readiness composition run, then reproduced under repetition: ~1 in 17 process runs hung ~600 s). Missing output was buffering loss on kill, so a DbgHelp stack walker was built (`build/diag/StackDump.cpp`, untracked) and captured the exact hang: main thread `VolumeSessionManager::~VolumeSessionManager` → `Stop` → `std::thread::join`; worker thread inside `ReconciliationSchedulerLoop`'s `wakeCv_.wait_for(lock, kSchedulerPollInterval{10 minutes}, ...)`.
- Root cause: `VolumeSessionManager::Stop` set `running_ = false` and called `wakeCv_.notify_all()` **without holding `wakeMutex_`**; the notification could land between the scheduler's predicate re-check and its `wait_for` registration and be lost, so `join()` waited out the full 10-minute poll interval. A production shutdown stall, not just a test defect.
- Fix (`d2b9d82`): publish the stop under `wakeMutex_` before notifying. Regression guard added to `tests/engine/test_volume_session_manager.cpp`: 2000 immediate Start/Stop iterations (pre-fix a hit stalls for ten minutes and trips the 120 s CTest timeout; post-fix the whole suite runs in ~1.2 s).
