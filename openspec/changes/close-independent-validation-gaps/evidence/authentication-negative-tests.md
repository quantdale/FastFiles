## Fixture handling

`tests/engine/AuthenticodeFixture.ps1` generates only uniquely named
`TEST CERTIFICATE / NON-PRODUCTION` roots/leaves in the CurrentUser personal
store, signs a copy of the test PE with the Windows SDK `signtool.exe`, and
uses an in-memory `CustomRootTrust` chain policy to isolate validity from the
default WinTrust trust decision. It removes the leaf, root, temporary PE,
state, and thumbprint files through a cleanup action. The C++ test checks the
cleanup exit code and file absence after every case. No CurrentUser Root entry
or PFX is generated by the runtime fixture harness.

The release-tooling fixture matrix separately covers self-signed and untrusted
cases through the production Windows trust policy, and missing-EKU,
expired, not-yet-valid, and valid cases through a private in-memory
`CustomRootTrust` seam. That seam makes the test root trusted without changing
the host trust store, so the EKU and validity failures are independently
observable. Every CurrentUser personal-store fixture cleanup is verified. The
valid case is explicitly marked `TEST CERTIFICATE / NON-PRODUCTION` and is not
authorized production evidence.

## Revocation boundary

Release signer preflight reports `NOT_CHECKED_OFFLINE` and does not require an
online OCSP/CRL result. It independently requires current validity, Code
Signing EKU, and a fully trusted Windows chain. Runtime WinTrust keeps
`WTD_REVOKE_NONE` so peer authentication remains offline; this is documented
as a separate revocation fact, not as proof that revocation is good.
