ostSignature` (:798–813) and rebuild failure closes the store (:815–816). Rebuild re-derives classification from `entries` with the current host table (:620–624).
### Findings
- **Finding: P1 — Q4 answer is NO; the fallback stream is not a canonical superset for non-ASCII needles.** `Store.cpp:1706–1711` (`name LIKE ? ESCAPE '\' OR name GLOB '*[^ -~]*'`). **Counterexample:** name `"Sand_probe_x.txt"` (pure ASCII), needle `u"\u017Fand_probe"` (long-s + `and_probe`) on any host where `CompareStringOrdinal(ſ, S, TRUE) == CSTR_EQUAL` — the exact host class the code itself premises (FoldClassification.h:12–13 "U+017F … uppercases to 'S'"). The needle is non-ASCII → ineligible → fallback. `CanonicalContainsName` returns TRUE at offset 0, but LIKE misses (name lacks the `C5 BF` bytes) and the GLOB disjunct misses (pure-ASCII printable name) → the canonical match is never streamed. Same with `u"\u212A"` (Kelvin) vs a name containing `K`. The hole is in the pre-existing stream, but this change newly claims it as the correctness backstop ("Any failure or ineligible shape falls through to the canonical stream below", Store.cpp:~1645) and the new test claims proof "for every needle" (test:476). **Smallest fix:** bind a `needleHasNonAscii` flag and `OR ?flag=1` into the fallback predicate (non-ASCII needles stream the full table; the caller re-verifies anyway), or explicitly narrow the claimed contract and the test wording.
- **Finding: P2 — the rung silently under-matches an un-folded ASCII needle (diff-caused regression hazard).** DDL is `tokenize="trigram case_sensitive 1"` (Store.cpp:106–107) and the eligibility gate (Store.cpp:1652–1654) checks ASCII + length ≥ 3 but **never folds or validates the fold**. **Counterexample:** needle `"REPORT"` (ASCII, len 6) vs name `"REPORT_beta.txt"`: pre-change `LIKE '%REPORT%'` matched case-insensitively; now the rung runs, `MATCH '"REPORT"'` finds nothing case-sensitively against the stored folded `report_beta.txt`, and returns without falling through (Store.cpp:1703) — zero rows, silent. The contract says "asciiFoldedNeedle" and the test folds deliberately (test:452–456), so this only bites a caller that skips the fold — which I could not verify inside the scoped reads. **Smallest fix:** apply the ASCII fold to the needle inside the rung before building the phrase (3 lines), making the forgiving pre-change behavior unconditional.
- **Finding: P2 — Q5: the superset differential is real, but the "red-first mechanism proof" is partially vacuous (path-attribution gap).** `test_store_read_session.cpp:477–480, 331–341, 493–495`. No assertion pins that the **candidate rung** produced the stream: if the rung never executed (statement invalid, gate mis-gated → fallback), row 105 still streams via the fallback GLOB disjunct (its name carries non-ASCII bytes), and every check — `supersetHolds`, `longsRowVisited`, `longsRowFoldedLacksNeedle`, the reopen check — still passes. Likewise the "zzz" bound check asserts `⊆ nonAsciiClass` (satisfied by the fallback), not `==` the sharp side-set. Additionally the red condition is synthetic (SetTestingFoldExceptionalUnit at :415 alters classification only, not the real `CompareStringOrdinal`, so on non-folding hosts no *real* canonical match is saved), and the exceptional unit sits at name index 0 (name 105, :426) — a first-unit-only rule bug would pass. **Smallest fix:** assert exact streamed sets (`"zzz"` → exactly `{105,106}`; `"sand_probe"` → exactly `{105,109}`), and place a fold-exceptional unit mid-name in a fixture row.
- **Finding: P3 — FoldOverrideCache is written but never read; comment mismatch; negative injection is fail-open.** FoldClassification.h:65–71 claims "the override is consulted BEFORE the host probe", but `UnitMayFoldToAscii` (:33–58) reads only `FoldProbeCache`; the override works solely via write-through in `SetTestingFoldExceptionalUnit`. That write with `exceptional=false` stores verdict 1, *suppressing* a genuine host probe — contradicting "fail-closed for the injected unit" (:70). Test-seam only (production never injects). Smallest fix: delete the dead cache or consult it first, and fix the comment.
- **Finding: P3 — Q3 residual: host-signature check is open-time only.** Store.cpp:798–815. Two processes with divergent host ordinal tables concurrently sharing one DB (e.g., over a share) can serve each other's classification; no per-query revalidation. Outside the single-machine model the design assumes — report only.
- **Finding: P3 — the open-time integrity cross-check cannot detect a stale/missing `name_folded` row.** Store.cpp:799–800 compares `COUNT(entry_name_index_map)` vs `COUNT(entries)`; an FTS-row loss with counts intact would pass. Soundness rests entirely on the transactional co-maintenance (Store.cpp:1273–1281) — fine today, fragile as an invariant-checker claim.
### Answers at a glance
- **Q1:** No absence possible for eligible needles *given the folded-needle precondition* — fold-exceptional units are side-set-caught, surrogates cannot occur in an ASCII match window (over-inclusion only), and name updates/partial upserts are transactionally co-maintained. The one live hole is the P2 unfolded-needle trap.
- **Q2:** Yes, complete on any host (exhaustive 128-ASCII probe with the matcher's own call, fail-closed).
- **Q3:** Not in the single-host model (rebuild-before-consult, marker state machine sound); only the two P3 scenarios above.
- **Q4:** **No** — P1 counterexample above.
- **Q5:** Differential is genuine; mechanism claims are underdetermined (path-attribution gap + synthetic red + first-unit placement).
**One-line verdict on 'CanonicalMatches ⊆ CandidateSet':** TRUE for eligible, pre-folded ASCII needles (FTS trigram ∪ sharp side-set is a host-independent superset); FALSE as a general claim — non-ASCII needles with fold-exceptional units canonically match pure-ASCII names that neither the rung nor the fallback ever streams.
**Merge verdict: OK with notes** — the candidate rung itself meets its superset contract; the P1 (fallback hole + overclaimed test/contract) must be fixed or the claimed contract narrowed before release, and the P2 needle-folding trap should be closed at the same time.
