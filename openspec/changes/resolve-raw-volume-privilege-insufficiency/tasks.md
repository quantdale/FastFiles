## 3. Make deployment signed and reversible

- [x] 3.1 Enforce non-placeholder mutual-authentication pins and signed Service/Engine artifacts before enabling the production privileged path. — **complete, fail-closed by construction and now unit-tested**: `VerifyPinnedSignature` (AuthenticodeVerification.cpp) rejects every peer while pins are all-zero placeholders (`IsPlaceholderThumbprint`) and otherwise requires a WinVerifyTrust-verified signature whose signer thumbprint exactly equals the pinned one; both ends of the boundary enforce it (service-side `ClientAuthentication.cpp` at handshake + periodic re-validation, engine-side `PrivilegedConnection::VerifyServiceIdentity` after image-path/install-dir checks, surfacing `UnavailableReason::UnverifiedServiceIdentity` so the UI degrades rather than trusting an unverified peer). New `tests/engine/test_authenticode_verification.cpp` (target `ffengine_authenticode_verification_tests`) pins the contract: unconfigured pins reject everything (even nonexistent paths), unsigned binaries rejected with a configured pin, signed binary rejected on pin mismatch, and accepted when the pin matches its real re-derived thumbprint (exercised against a Microsoft-signed system binary). The production privileged path stays disabled until the release signing pipeline provisions real pins.
- [x] 3.2 Add transactional backup, upgrade, startup verification, and rollback for service binaries, configuration, rights, and security descriptors, restoring the prior known-good state after any failed verification. — **complete**: `InstallSteps.cpp` snapshots the installed binaries (`FastFilesIndexSvc.exe`/`FastFilesEngine.exe`/`FastFiles.exe`/`FastFilesSetup.exe`) plus the prior SCM account configuration (`type=`/`name=` in `Backup\install-state.txt`, fails closed if unreadable) into `<installDir>\Backup` before any binary is replaced; on post-install startup-verification failure `RestoreServiceState` unregisters the half-configured new service, restores the old binaries, re-registers with the prior account configuration, and restarts the service, so an upgrade never leaves a broken half-installed service. Live end-to-end rollback run remains part of task 4.1.
- [x] 3.3 Verify that the diagnostic unsigned build switch is unavailable from release artifacts and cannot weaken production installation checks. — **complete and guarded at configure time**: `FASTFILES_DIAGNOSTIC_ALLOW_UNSIGNED` is now a CMake option (default OFF, `src/setup/CMakeLists.txt`) that is only ever defined for Debug builds — a non-Debug configure with the option set fails with `FATAL_ERROR` (verified: Release configure rejected). No preset sets it, so debug/release/analyze builds all compile the strict fail-closed pin path; release artifacts can therefore never carry the escape hatch.
