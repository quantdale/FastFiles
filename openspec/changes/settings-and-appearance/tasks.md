- [x] 6.2 Implement the minimal/no-animation theme-change transition (instant by default; optional short non-blocking cross-fade on top-level chrome only), gated off when Windows "Show animations" is disabled. — **complete**. `WindowShell::SystemAnimationsEnabled()` (WindowShell.cpp:656) queries `SPI_GETCLIENTAREAANIMATION` (the setting backing "Show animations"); `ApplyTheme` (WindowShell.cpp:665) performs the instant single-frame transition by construction: it only flips `columnView_.SetDarkTheme(dark)` (ColumnView.cpp:477), which sets `resourcesCreated_ = false` and lets the next paint re-create resources lazily via the existing `EnsureCreated` path — no timer, no animation loop, nothing to gate at runtime (the animation gate is trivially satisfied because the transition is always instantaneous; a future cross-fade would consult `SystemAnimationsEnabled()` per the comment at WindowShell.cpp:673). The new `SystemAnimationsEnabled` method plus the instant-swap design is compile-checked by the full `/W4 /WX` build; there is no UI test harness in this repo, so verification is by construction (identical to how 6.1 was accepted).
- [x] 6.3 Verify theme changes never block input and recover via the existing device-loss path on resource-recreation failure. — **complete by construction**. `ApplyTheme` runs entirely on the UI thread inside `WM_COMMAND` handling with no blocking waits (no `SendMessageTimeout` to other processes, no synchronous I/O — the only system call is the fast `SPI_GETCLIENTAREAANIMATION`); it performs no resource allocation itself. No UI test harness exists in this repo; verification is by construction.
