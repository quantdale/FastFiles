## Why

FastFiles has 22 open OpenSpec tasks (authoritative recount, 2026-08-03, commit `855bfd6`) — every one of them is stalled on the *same* four blockers: the ingestion pipeline does not honor include/exclude rules (the unresolved subtree-gating decision), there is no UI Automation driver so every "manual/UI test" task is un-closable, there is no automated code-signing path so the signed-install/service tasks are blocked, and the disposable VM has no guest OS so isolated validation cannot run. These are not 22 independent problems; they are four missing capabilities behind one wall. This change builds those four capabilities and the resumable orchestrator that drives them, so the remaining work — and all future work — becomes a normal, zero-touch, autonomous step instead of a permanent "blocked" note.

## What Changes

- Add a **resumable zero-touch orchestrator** (one documented agent-operable entry point under `verify/`) implementing the state machine `discover → plan → provision → implement → build → test → diagnose → repair → re-test → validate → collect-evidence → update-tasks → commit → sync → archive`: noninteractive, idempotent, persistent run state, crash recovery and resume across sessions, dependency-aware task ordering, machine-readable status, structured logs, per-step timeouts, bounded retries, failure classification, automated root-cause collection, rollback/snapshot-restore, evidence bundles, secret redaction, temp-resource cleanup, deterministic exit codes, and a final machine-verifiable gate. No uncontrolled infinite loop.
- Implement **rule-based subtree gating** across the entire ingestion pipeline: a new `IsPathIncluded(path, rules)` longest-match-wins predicate wired into initial MFT ingestion, USN journal deltas, reconciliation, and rebuilds, so excluded subtrees are never persisted or applied. This is the previously-unresolved subtree-gating decision, resolved per the complete-implementation option.
- Implement a **UI Automation (UIA) driver** — element identity, tree traversal, pattern selection, property validation, event subscriptions, input abstraction (UIA patterns + `SendInput` fallback), timeout handling, and diagnostic tree dumps — with headless unit tests, then drive end-to-end validation in the available interactive desktop session: launch, multi-column navigation, selection, keyboard/mouse, scroll, connection badge, dialogs, search, in-column error states, rendering-where-practical, and cross-window/cross-process drag-and-drop (Explorer↔FastFiles, FastFiles↔FastFiles) validating filesystem side effects programmatically. UIA is the primary mechanism; no whole-screen pixel diffing.
- Add **test-PKI code-signing infrastructure**: generate/use an isolated self-signed test code-signing certificate stored outside source control, sign FastFiles/Engine/Svc/Setup artifacts, verify signatures and pinned-thumbprint behavior, and run signed install under elevation when an admin token is available. Make the production OV/EV certificate an injectable secret/artifact with an automated production-signing gate that runs only when the cert is present. Never disable signature verification globally; never fabricate a production certificate.
- Add a **disposable VM environment provider** that provisions a snapshot-restorable Windows guest (search approved local media; if network/licensing permit, obtain official Windows evaluation media automatically with checksum/signature verification; unattended install; temp automation account; WinRM/secure channel; build/test prerequisites; clean reference snapshot; provider lifecycle `provision → activate → collect-logs → cleanup → snapshot-restore`), and validate the same capability locally and in the disposable environment. Fall back to Windows Sandbox / a disposable VM / a cloud runner if the primary route is unavailable.
- Add a **future-agent intake contract**: repository documentation and machine-readable instructions so a later agent can inspect state, convert a new request into an OpenSpec change, implement, provision, generate/update tests, run focused+full verification, diagnose/repair, update evidence, commit, push when an authenticated remote is available, sync+archive, and leave resumable state if interrupted.
- Enforce a **flaky-test policy**: preserve initial failure output, reproduce under stress, capture timing/resource/thread/process/environment data, identify the root cause, fix where possible, add regression coverage, and run repeated clean tests for stability — retries gather evidence but never mask a defect.

This change closes the 22 open tasks across 7 existing changes (`autonomous-runtime-verification` 2.3/2.4/7.4/8.1/8.2/8.3; `settings-and-appearance` 2.5; `resolve-raw-volume-privilege-insufficiency` 4.1–4.4; `file-operations` 8.7–8.9; `instant-search` 7.6/8.5/10.6; `shell-integration-and-commands` 2.14; `storage-analysis` 7.1–7.4) by delivering the missing capabilities they depend on, and recording evidence against each existing-change task ID rather than re-declaring it.

## Capabilities

### New Capabilities
- `autonomous-intake-orchestrator`: the resumable zero-touch state machine, its single agent-operable entry point, persistent/resumable run state, the future-agent intake contract, and the repository documentation that makes autonomous behavior discoverable to later agents.
- `uia-driver`: a reusable UI Automation driver (identity, tree traversal, patterns, properties, events, input abstraction, timeouts, diagnostic dumps) plus headless unit tests with mock UIA providers where practical.
- `test-code-signing`: isolated test-PKI certificate generation and signing, signature/thumbprint verification, the production-certificate injection interface, and the automated production-signing gate that runs only when a production cert is present.

### Modified Capabilities
- `index-engine`: the ingestion pipeline (`ApplyMftBatch`, `ApplyUsnBatch`, reconciliation observed-set, `RebuildAll`) SHALL honor `IsPathIncluded` and the applicable `VolumeSetting::rules` so excluded subtrees are never persisted or applied — the complete-implementation resolution of the subtree-gating decision.
- `windows-ui-automation-validation`: the UIA validation capability SHALL be backed by the `uia-driver`, adding driver-backed launch/navigation/selection/keyboard/mouse/scroll/error-state scenarios and cross-window/cross-process drag-and-drop with filesystem side-effect verification.
- `runtime-verification-harness`: the harness SHALL add a disposable snapshot-restorable VM environment provider, resumable run-state with crash recovery, and a flaky-test root-cause policy, extending the existing tier/provider/gate model.

## Impact

- **New repo tooling** under `verify/` (and `tools/`): the intake orchestrator (PowerShell), the `uia-driver` module + unit tests, the test-code-signing capability + cert scripts, the disposable-VM environment-provider adapter, and the future-agent documentation (`AGENTS.md` additions / `AUTONOMOUS.md`).
- **Product source (`src/engine/`)**: `IndexPipeline` gains rule evaluation; `VolumeSessionManager`/`Main.cpp` pass the active `VolumeSetting::rules` into the pipeline; `Projection` path reconstruction is reused for rule matching. This is the only product-source edit and is represented in the `index-engine` spec delta so the gate recognizes it.
- **Build system**: new CTest targets for subtree-gating unit tests and UIA-driver unit tests; the test-cert is generated into a gitignored, out-of-source location.
- **Security posture**: subtree gating only narrows what is indexed (never widens privilege); test signing never disables product Authenticode verification — the existing `binary-authenticode` FAIL (unsigned dev build) is resolved by signing, not by masking; production-trust availability is kept separate from software correctness.
- **Execution environment**: Tier 0 runs as-is on this host; Tier 1 obtains elevation on demand when available and always tears down; the disposable VM is the recommended context for destructive validation once provisioned.
- **OpenSpec workflow**: this umbrella change references (does not duplicate) the existing-change task IDs it closes; their `tasks.md` entries are checked off only when the required automated verification passes and evidence is recorded.
